# ALMP v8.2.2

**Download:** `ALMP-v8.2.2-Portable.zip`
**SHA-256:** 5E9723F85CF6358B0794CC37877A675C75D58AAF05A1FBEE06CF9F575978550A

A speed fix release for v8.2.1. Everything else is the same as v8.2.0 and v8.2.1
([v8.2.0 notes](v8.2.0.md), [v8.2.1 notes](v8.2.1.md)). ALMP still starts clean and never connects to the internet.

## Fixed
- **ALMP could take a very long time to open (up to a minute or more).** Double-clicking a video sometimes left
  you waiting 5 to 70 seconds before the window appeared and the video played.

  **Why:** the cause was the number of fonts installed on the PC, not the video or the drive. The Qt toolkit
  that draws ALMP's window looks through every installed font in three situations: the first time it needs
  any text (Qt's newer DirectWrite font list), when it is asked for a "semi-bold" weight that the Segoe UI font
  does not have as a plain style, and when it must draw a character that Segoe UI does not have (the ✓ in
  the audio/subtitle menu). A normal Windows PC has a few hundred fonts, so this costs little. The test PC has
  **9,223 fonts**, and each of those searches took 5 to 70 seconds.

  **What changed:**
  - ALMP uses Qt's older GDI font list on Windows (Qt's default until Qt 6.7). It lists the same fonts in about
    0.05 s instead of 5 to 70 s. If you set `QT_QPA_PLATFORM` yourself, ALMP leaves your setting alone.
  - Semi-bold text uses the "Segoe UI Semibold" font by name. It looks the same and needs no search.
  - The audio track and subtitle menus show Qt's own check mark instead of a ✓ character. The first time the
    menu opened it used to freeze for about 6 s on the test PC.
  - A file you double-click now starts at once. ALMP used to wait 250 ms first; that wait is still used when
    several files are opened together.
  - ALMP writes two start-up times to its log (`%LOCALAPPDATA%\ALMP\almp.log`): "window shown after X s" and
    "playing after Y s". A slow start can now be seen there.

## Measured
Windows 11 PC, 4 logical cores, 32 GB RAM, 9,223 fonts installed. ALMP and the video (a 182 MB MP4) are on a
hard disk (HDD). The times run from starting ALMP with the file (as a double-click does) to the window appearing
and the video playing.

| | v8.2.1 | v8.2.2 |
|---|---|---|
| Window appears | 4.0 to 36.9 s (11 starts; the first start in each test batch took 13 to 37 s) | 0.7 to 0.8 s (every start) |
| Video playing | about 1 s after the window (8.2.1 does not log it; 8 to 28 s in total from source) | 1.5 to 1.7 s after starting ALMP |
| First start of a freshly copied ALMP | (not measured) | 3.2 s until playing |
| Qt's font list on its own, first use | 5 to 70 s (Qt's DirectWrite font list) | 0.05 s (GDI font list) |

What is still slow, and why:
- The first start after the ALMP files were changed or copied can take a few seconds longer before ALMP's own
  code runs. Windows reads the program files from the disk, and the antivirus checks them (loading the
  118 MB playback engine `mpv-2.dll` for the first time took about 1 s extra on the test PC).
- If a file name contains characters that Segoe UI does not have (for example Chinese or Japanese titles, or
  emoji), Qt still searches the installed fonts once to find one that has them. On a PC with thousands of
  fonts that can take several seconds the first time such a name is shown. On a normal PC it is quick.
- I could not test a true "cold" start (first start after Windows starts) on the test PC.

## Checked
- `tools/bench_startup.py` (new) starts the real ALMP with a video several times and reads the start-up times
  from the log. The numbers above come from it and from timing the window directly.
- New tests: the Windows font setting, the user's own setting winning, no unfinished style-sheet placeholders,
  semi-bold using its own font, real check marks in the track menus, and no ✓ character left in the window code.
- ruff and the test suite pass.

## For developers
- `almp/app.py`: new `qt_platform_override()`; sets `QT_QPA_PLATFORM=windows:fontengine=gdi` before
  `QApplication` unless the user set it. Logs "Start-up: window shown after X s".
- `almp/theme.py`: new `SEMIBOLD` style (Segoe UI Semibold on Windows) replaces `font-weight: 600`.
- `almp/ui.py`: track menus use checkable actions; `open_external(paths, wait_ms=250)` (0 for the files ALMP
  was started with); logs "Start-up: playing after Y s" on mpv's first `playback-restart`.
- `almp/logsetup.py`: `seconds_since_start()`.
- New `tools/bench_startup.py`. No new dependencies. libmpv pin unchanged.

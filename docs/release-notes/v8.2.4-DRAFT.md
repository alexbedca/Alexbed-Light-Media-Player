# ALMP v8.2.4 (DRAFT - not released)

**Status:** work on branch `v8.2.4`, not pushed, not released. Version number not bumped yet (still 8.2.3
in `almp/__init__.py`). Final notes, zip and SHA-256 come with the release.

ALMP still starts clean, keeps big playlists instant, and never connects to the internet.

## New
- **Show subtitles (Settings > Subtitles).** Remembered between runs; **off by default** (subtitles are
  hidden until you turn them on). The subtitles menu (right-click the video, or the subtitles button) uses
  the same setting: *Off* there unticks the Settings box, picking a subtitle turns it on. Applied at start
  and for every new file. Loading a subtitle file turns it on.
- **ALMP leaves nothing on the PC.** Settings, saved places and the log now live in a `Data` folder next to
  `ALMP.exe`. Deleting the ALMP folder removes everything. If that folder cannot be written to (Program
  Files, read-only USB stick), ALMP uses `%APPDATA%\ALMP` and `%LOCALAPPDATA%\ALMP` as before, and
  Settings > *Privacy and files* says so.
  - **First start after updating:** `settings.json`, `positions.json` and `startup_target.txt` are copied
    from `%APPDATA%\ALMP` into `Data`, each copy is compared byte for byte, and only then are ALMP's own
    old files deleted by name (the same list as `Remove-ALMP-Defaults.bat`). The old folders are removed only
    if nothing else is in them.
  - The only things ALMP can still put outside its folder are the Windows entries you turn on yourself:
    Default apps / "Open with", the right-click menu entries, and the Run at Startup shortcut.
- **Small log, cleared on close.** At most 256 KB plus one older copy. Settings > *Privacy and files* > Log:
  *Clear it when ALMP closes* (default; kept if something went wrong during that run), *Keep the last run*,
  or *Off*.
- **All / Video / Audio** buttons under the playlist search: by file type (extension) only, no disk reads,
  combine with the search.
- **Save playlist: Ctrl+S.** With a search or the Video/Audio filter on, only the shown items are saved
  (the dialog title says so).
- **Format of the playing track** next to the time, e.g. *FLAC - 24-bit / 96 kHz* (read from that one file
  only; nothing is scanned for the playlist).
- **Gapless playback** (Settings > Music, off by default): ALMP tells mpv which track comes next, so mpv
  reads it ahead and goes on without a gap.
- **Exclusive audio** (Settings > Music, off by default, remembered): WASAPI exclusive mode, bit-perfect,
  for external DACs and AV receivers. Other programs and Windows sounds are silent while ALMP plays.
- **Video upscaling** (Settings > Playback): *Standard* (as before) / *Sharp* (spline36) / *High quality*
  (ewa_lanczossharp + correct downscaling, sigmoid upscaling, debanding). mpv's own built-in scalers only;
  nothing is downloaded or bundled. Changes apply at once.
- **Help > About** shows the Releases page address with a **Copy link** button (copies the text only;
  ALMP opens nothing and checks nothing).

## Fixed while testing
- (found during 8.2.4 work) The format text read mpv *runtime* values with python-mpv's `player["..."]`,
  which only reads mpv *options*; fixed before release.

## Checked, no change needed
- **Fullscreen with a mixed playlist** (video -> FLAC -> video): ALMP stays fullscreen, shows the album art
  (or the ALMP logo on dark) for music, and the next video plays fullscreen again.

## Tests and measurements (this PC: Windows 11 Pro, 4 cores, GTX 960, 1920x1080)
- Automatic tests: 304 pass (57 new in `tests/test_v824_features.py`), `ruff check .` clean.
- Playlist benchmark `tools/bench_playlist.py --sizes 100000`, before -> after (same PC, same day):
  first track 0.347 -> 0.347 s, whole list 1.71 -> 1.78 s, search "e" 13.0 -> 13.2 ms,
  sort by name 1.30 -> 1.25 s, window stall p99 22.7 -> 23.5 ms (max 335 -> 336 ms, one tick at the end).
  Within run-to-run noise.
- 25,000 items in the real window (offscreen, median of 5): search 4.2-6.5 ms (before 4.4-6.5 ms);
  sort by name 316 ms (before 317 ms); new type filter 3.5-3.7 ms (first use builds a small cache: worst
  15.6 ms). 100,000 items: type filter 7-9 ms (first use 42 ms).
- Upscaling, fullscreen on the 1080p screen, 10 s per level, mpv `frame-drop-count` /
  `decoder-frame-drop-count` / `vo-delayed-frame-count` all **0** at every level:

  | Video | Standard | Sharp | High quality | High + extras |
  |---|---|---|---|---|
  | 720p25 (software decoding) | 19% GPU | 23% | 12% | 12% |
  | 360p30 (d3d11va) | 12% | 18% | 43% | 44% |

  GPU = average 3D-engine use of ALMP from Windows performance counters (noisy; 720p numbers vary with
  what the decoder is doing). High quality roughly triples GPU work on low-resolution video: fine on this
  GTX 960, may stutter on weak laptop graphics (the Settings text says so). Default stays Standard.
- Gapless (real mpv): FLAC -> MP3 switched with 0 reloads by ALMP; not listened to.
- Exclusive audio (real mpv): `current-ao` wasapi, playback continued; not tried with an external DAC.
- Built `ALMP.exe` (Nuitka, copy in a scratch folder), `tools/bench_startup.py "Christmas 2026.mp4" --runs 3`:
  window shown 0.7 s, playing 1.6-1.7 s (3 of 3 runs; target ~1 s / 1.5-2 s). The very first start, which
  also moved old settings into `Data`, took 1.3 s / 2.4 s.
- Built `ALMP.exe` with fake old `%APPDATA%\ALMP` / `%LOCALAPPDATA%\ALMP` folders: `Data` appeared next to
  `ALMP.exe`, the old settings (volume 37) were kept, the old folders were removed, and after a normal close
  only `Data\settings.json` was left (the log was cleared).
